# Round 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (native). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Demo sign-in on the sign-in page (safely scoped), new sign-in page and logo, analytics-first dashboard with one KPI bar, L&D as System Admin, no audit-log screen.

**Architecture:**
- The demo scope is enforced in the services: a SQL filter on list queries, and assertions on by-id reads and writes.
- The UI only reflects it.
- System-admin checks go through one helper.

**Tech Stack:** Next.js 16 App Router, Drizzle/Postgres, iron-session, Tailwind 4, Vitest, Playwright, Pillow (asset prep).

**Spec:** `docs/superpowers/specs/2026-10-15-round3-login-dashboard-access-design.md`

## Global Constraints

- Demo domain: `@demo.wct.my`. Env switch: `DEMO_LOGIN=true`.
- Copy:
  - "Head of Departments"
  - "L&D Team (System Admin)"
  - "Demo accounts can look at settings but can't change them."
  - "Try a demo account"
- No Microsoft logo is drawn or committed by us.
- No secrets in git.

## Review Focus

1. A demo HR Head/L&D (who "see everything") must not see real requests anywhere: dashboard, history, approvals, analytics, Excel export, PDF, attachment download.
2. A cross-site POST to demo-login must not sign anyone in (Origin check).
3. A real L&D user must reach Admin settings. A demo L&D must see them read-only, with only demo people listed.
4. Revoking the last of the SYS_ADMIN+LND holders is refused.
5. With `DEMO_LOGIN` unset in production, the sign-in page shows no demo section and the route answers 404.
